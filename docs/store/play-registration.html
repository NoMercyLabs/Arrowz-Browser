Only you can do these

Needs you
  1. Create the app in the console under the NoMercy Labs developer account, with the app name and package below. Nothing else can start until the package exists there.
  2. Publish the privacy policy at a public URL. It is a hard requirement and the console will not accept the listing without it. The text is written and final; it needs hosting.
  3. Add PLAY_SERVICE_ACCOUNT_JSON to the repository secrets. The release workflow already reads it and skips publishing silently when it is absent, so the tag looks successful and nothing reaches the console.
  4. Complete the EU DSA trader declaration on the developer account. It blocks distribution in the EU, which is where you are.
  5. Grant production-track rights on the account if you want promotion beyond internal testing. Internal works without it.

Once the service account secret is in place, re-running the v0.1.0 release workflow publishes the existing build to internal testing. Nothing needs rebuilding.

Store listing text

Answers ready

Short description 76 / 80

A private browser for Android TV. No trackers, no accounts, six remote keys.

Full description 1,502 / 4,000

Arrowz Browser is a web browser built for a television and a remote, rather than a phone browser with the buttons moved around.

It works with the remote you have. Everything is reachable with the four arrows, OK and BACK. Nothing needs a color button, a mouse, or a phone app. Pages you can navigate by focus are walked link by link with a focus ring you can see from the sofa; pages you cannot are given a pointer that moves and clicks. It chooses for you, and a long press on OK overrules it.

Forms are native. A text field on a page opens a real television keyboard with the right layout for the field, and a dropdown becomes a list you can actually operate with a D-pad, instead of one that ignores you.

Video behaves like a browser, not a webview. Fullscreen, now playing, media keys, audio focus, background audio and picture-in-picture all work.

Trackers are blocked by default, using the same public filter lists desktop blockers use, downloaded from their publishers directly. The app never contacts a server of ours, because there isn't one.

Nothing is collected. No analytics, no crash reporting, no advertising identifiers, no account. Google Safe Browsing is turned off, which is the component that reports browsing to a third party, and that trade-off is stated plainly in the privacy policy rather than buried.

Netflix, Prime Video and Disney+ refuse browser playback by policy, and no browser on any platform gets around that. Other paid video that uses standard web DRM plays.

Data safety

Answers ready

Does your app collect or share any of the required user data types?

No. There is no code path that could. No analytics dependency, no crash reporter, no advertising library, no account system, and CI fails the build if one is added.

Is all user data encrypted in transit?

Not applicable, because no user data is transmitted. Browsing itself uses HTTPS wherever a site offers it, an HTTPS page cannot pull HTTP subresources, and certificate errors are cancelled with no way to click through.

Do you provide a way for users to request data deletion?

Everything the browser stores is on the device. Clearing app data removes it, and so does uninstalling. There is nothing held anywhere else to delete.

The one request the app makes on its own behalf is a weekly filter-list download from easylist.to and raw.githubusercontent.com. It goes to those publishers directly and carries nothing about the user beyond what any download requires. Disclose it; it does not make the collection answer yes.

What a reviewer may ask about

Have the answer ready
  • Safe Browsing is off. EnableSafeBrowsing is declared false in the manifest deliberately: it is the WebView component that reports browsing activity to a third party, and the app's whole claim is that browsing does not leave the device. It is disclosed in the privacy policy rather than hidden.
  • Cleartext HTTP is allowed. A browser that cannot open http:// cannot reach a router admin page, a NAS, a printer or the older web. The security-relevant half is kept: an HTTPS page still cannot pull HTTP subresources, and certificate errors are never overridable.
  • The high content rating is intentional and follows from declaring uncurated web access truthfully.
