## Short description

A private browser for Android TV. No trackers, no accounts, six remote keys.

## Full description

NoMercy Browser is a web browser built for a television and a remote, rather than a phone browser with the buttons moved around.

**It works with the remote you have.** Everything is reachable with the four arrows, OK and BACK. Nothing needs a color button, a mouse, or a phone app. Pages you can navigate by focus are walked link by link with a focus ring you can see from the sofa; pages you cannot are given a pointer that moves and clicks. It chooses for you, and a long press on OK overrules it.

**Forms are native.** A text field on a page opens a real television keyboard with the right layout for the field, and a dropdown becomes a list you can actually operate with a D-pad, instead of one that ignores you.

**Video behaves like a browser, not a webview.** Fullscreen, now playing, media keys, audio focus, background audio and picture-in-picture all work.

**Trackers are blocked by default,** using the same public filter lists desktop blockers use, downloaded from their publishers directly. The app never contacts a server of ours, because there isn't one.

**Nothing is collected.** No analytics, no crash reporting, no advertising identifiers, no account. Google Safe Browsing is turned off, which is the component that reports browsing to a third party — and that trade-off is stated plainly in the privacy policy rather than buried.

Netflix, Prime Video and Disney+ refuse browser playback by policy, and no browser on any platform gets around that. Other paid video that uses standard web DRM plays.

## Data safety declaration

**Does your app collect or share any of the required user data types?** No.

That answer is defensible because there is no code path that could. The app has no analytics dependency, no crash reporter, no advertising library and no account system, and CI fails the build if one is added. The only request the app makes on its own behalf is a weekly filter-list download from `easylist.to` and `raw.githubusercontent.com`, which goes to those publishers directly and carries nothing about the user beyond what any download requires.

**Is all user data encrypted in transit?** Not applicable — no user data is transmitted. Browsing itself uses HTTPS wherever the site offers it, mixed content is refused, and certificate errors are never overridable.

**Do you provide a way for users to request data deletion?** Everything the browser stores is on the device. Clearing app data removes it; so does uninstalling. There is nothing held anywhere else to delete.

## Content rating questionnaire

A browser reaches arbitrary web content and is declared as such, truthfully, rather than rated as the app's own chrome would rate on its own.

- **Does the app allow users to access user-generated or uncurated web content?** Yes — it is a web browser with no content filtering.
- **Does the app contain violence, sexual content, or profanity of its own?** No. The app's own content is a browser interface.
- **Does the app share user location?** No, and it asks before a website may.
- **Does it allow users to interact or exchange content?** No, and it has no accounts.

The expected outcome is a high age rating. That is correct for a browser and is not something to work around.
